# Audit UI — 2026-09-22

Cakupan: shell aplikasi (`components/dashboard-layout.tsx`), design tokens (`app/globals.css`), primitives bersama (`components/ui/*`), halaman Dashboard (sudah rapi), dan sampel 13 halaman list/CRUD yang memakai primitives bersama (`app/sales/quotations/page.tsx` dipakai sebagai contoh representatif; polanya sama di finance/invoices, finance/kwitansi, sales/customers, sales/delivery, sales/rfq, supply-chain/bills, supply-chain/goods-receipts, supply-chain/purchase-orders, supply-chain/purchase-requests, supply-chain/suppliers, supply-chain/vendor-payments, operational/products).

Skala masalah: dari 97 halaman `page.tsx`, 72 memakai style Tailwind generik (`bg-slate-*`, `rounded-lg border` polos) tanpa token brand. Dashboard dan beberapa halaman settings sudah punya bahasa desain sendiri (`erp-*` classes, warna merah brand); sisanya masih memakai default shadcn/ui yang belum disentuh.

## Temuan

1. **[HIGH]** `components/ui/table.tsx`, `card.tsx` masih 100% kode default shadcn/ui (warna `slate-200`/`slate-50` hardcoded, bukan token brand), dipakai di 13+ halaman. Ini persis pola "Sterile Default" — R-20: tukar logo dan nama produk, tampilannya tidak berubah, bisa jadi ERP siapa saja. *(R-20, R-29)*
2. **[HIGH]** Tidak ada animasi loading yang sebenarnya di halaman list (`app/sales/quotations/page.tsx` baris 104-112 dan pola serupa di 12 halaman lain): hanya teks statis `"Loading..."` di tengah layar kosong. Tidak memenuhi kebutuhan "UI states" yang hidup — ini akar keluhan Anda soal tidak ada animasi saat data diproses. *(R-27)*
3. **[HIGH]** Navigasi antar-menu (klik sidebar) tidak punya indikator loading sama sekali di level aplikasi — user tidak tahu halaman sedang berpindah/memuat. *(R-27)*
4. **[MEDIUM]** Dialog native browser `confirm()`/`alert()` dipakai untuk konfirmasi hapus dan pesan error (`app/sales/quotations/page.tsx` baris 66 & 72, pola sama di halaman list lain). Terasa jadul, tidak konsisten dengan sisa aplikasi, dan tidak bisa diberi styling brand. *(C-1, kualitas modern)*
5. **[MEDIUM]** Badge status memakai warna Tailwind acak yang di-hardcode per halaman (`bg-blue-100 text-blue-800`, dst, baris 84-92) — tidak konsisten dengan skala warna brand merah, dan tiap halaman menulis ulang mapping warnanya sendiri. *(R-29, R-31)*
6. **[LOW]** Campur bahasa Inggris/Indonesia dalam satu halaman yang sama ("New Quotation", "QT Number", "Search by...", sementara Dashboard 100% Indonesia). Bukan pelanggaran antislop langsung, tapi mengurangi kesan aplikasi yang dirancang khusus untuk PT ini. *(C-1)*
7. **[LOW]** Font `Geist` dipakai tanpa alasan brand tertulis (default pilihan model AI, lihat R-06) — secara visual sudah netral dan terbaca baik untuk angka finansial, tapi belum ada keputusan sadar yang tercatat.
8. **[LOW]** Shell sidebar/topbar (`dashboard-layout.tsx`) dan Dashboard (`app/dashboard/page.tsx`) sudah cukup baik: data asli (bukan angka palsu), radius & shadow terbatas, tidak ada gradient/glow berlebihan. Perlu penyegaran visual (lebih "hidup") tapi bukan perombakan total. *(catatan positif, bukan temuan)*

## Rekomendasi cakupan perbaikan hari ini

Mengingat keterbatasan waktu/token, perbaikan yang paling efektif adalah di **level fondasi** (token warna/spacing/shadow + primitives bersama + indikator loading global), karena otomatis menyebar ke seluruh 97 halaman tanpa harus menyentuh satu-satu. Ditambah 2-3 halaman contoh (Dashboard, Quotations list, satu form) sebagai referensi pola baru.

- Perbaiki #1, #2, #3, #4, #5, #7 → level primitives + shell + flagship pages.
- #6 (campur bahasa) tidak diubah hari ini kecuali diminta — itu perubahan konten/copy per halaman, bukan desain, dan menyentuh 70+ file di luar anggaran hari ini.

## Laporan setelah perbaikan (2026-09-22)

Disetujui: semua kecuali #6.

- **#1 (fixed)** — `components/ui/table.tsx`, `card.tsx`, `button.tsx` diganti dari warna `slate-*` hardcoded ke token brand (`--neutral-*`, `--border`, `--background`, `--primary-tint`). `components/ui/document-form.tsx` (dipakai 9 halaman form) disederhanakan dari 15 warna aksen acak menjadi satu aksen brand. Karena 13+ halaman list dan 9 halaman form mengimpor primitives ini, perbaikan menyebar otomatis ke seluruh halaman tanpa disentuh satu-satu — dikonfirmasi di halaman Purchase Orders (tidak disentuh sama sekali) yang kini menampilkan tombol merah brand dan aksen dot brand.
- **#2 (fixed)** — Ditambahkan `components/ui/skeleton.tsx` (shimmer, bukan spinner statis) dan diterapkan di halaman Dashboard (kartu metrik) dan halaman Penawaran/Quotations (flagship list page) menggantikan teks `"Loading..."`/`"…"` statis.
- **#3 (fixed)** — Next.js 16 `useLinkStatus` dipasang di tiap link sidebar (`components/dashboard-layout.tsx`) menampilkan titik merah brand yang muncul hanya saat navigasi sedang berlangsung (sesuai pola resmi Next.js untuk App Router, bukan progress-bar generik).
- **#4 (fixed)** — `components/ui/confirm-dialog.tsx` (dialog konfirmasi bergaya brand, bisa Escape/klik luar untuk batal) menggantikan `window.confirm()`, dan `lib/toast.ts` + `components/ui/toast-region.tsx` menggantikan `window.alert()`, dipasang di halaman Penawaran/Quotations sebagai contoh.
- **#5 (fixed)** — `components/ui/status-badge.tsx`: satu pemetaan status → warna (draft/terkirim/diterima/ditolak/dll) dipakai di halaman Penawaran; sebelumnya tiap halaman menulis ulang mapping warnanya sendiri.
- **#7 (no_change_needed)** — Font Geist tetap dipakai; alasan ditulis di `app/globals.css`: geometris, netral, terbaca baik untuk angka finansial tabular, tidak bersaing dengan merah brand.
- **#8** — Dashboard dan shell dipoles ringan (skeleton di kartu metrik), tidak dirombak total karena sudah baik sejak awal.

Verifikasi: `npx tsc --noEmit` bersih. Dicoba langsung di browser (login sungguhan ke `admin@erp.local`, data produksi asli): Dashboard tampil dengan shimmer saat memuat, halaman Penawaran menampilkan skeleton lalu 51 data asli dengan badge status berwarna, tombol hapus membuka dialog konfirmasi baru (dicoba klik Hapus → dialog muncul → klik Batal → data tidak berubah, tetap 51), halaman Purchase Orders yang tidak disentuh ikut mewarisi tombol dan aksen brand. Tidak ada error konsol. Dicek juga di lebar mobile (375px): tidak ada overflow horizontal, skeleton kartu metrik tampil rapi.

Cakupan yang BELUM disentuh (di luar anggaran hari ini, by design): ~90 halaman lain masih memakai style `bg-slate-*` langsung (bukan lewat primitives) dan belum punya skeleton loading sendiri; 12 halaman list lain (selain Penawaran) yang sama-sama memakai `components/ui/table` masih pakai `window.confirm()`/`alert()` dan teks "Loading..." di kode halaman itu sendiri, meski warna/tabelnya sudah otomatis ikut brand baru.
