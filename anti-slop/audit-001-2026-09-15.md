## HIGH

### 1. Dead navigation — all 7 sidebar menu items 404
- **Rule:** R-24 (Hard Gate — Navigation)
- **File:** [components/dashboard-layout.tsx:21-30](components/dashboard-layout.tsx#L21-L30)
- **Finding:** The sidebar menu links to `/sales`, `/supply-chain`, `/operational`, `/finance`, `/hr`, `/reports`, `/settings`. None of these have a `page.tsx` — only `/dashboard` and deeper routes like `/sales/customers` exist. Every top-level menu item except Dashboard leads to a 404.
- **Reason it fails:** navbar links must have a real destination or be labeled "coming soon".

### 2. Dead buttons — "Aksi Cepat" panel does nothing
- **Rule:** R-26 (Hard Gate — Interactive Elements)
- **File:** [app/dashboard/page.tsx:109-120](app/dashboard/page.tsx#L109-L120)
- **Finding:** The four Quick Action buttons (Buat Penawaran Baru, Lihat Pesanan, Buat Invoice, Kelola Proyek) have no `onClick` and no `href`. Clicking them does nothing.
- **Reason it fails:** buttons with no real behavior and no `// TODO` + visible "coming soon" label are forbidden.

### 3. Fabricated company name, mismatched with real data
- **Rule:** R-38 / R-23 (Hard Gate — Real Content or Honest Placeholder)
- **Files:** [app/dashboard/page.tsx:38](app/dashboard/page.tsx#L38), [components/dashboard-layout.tsx:124](components/dashboard-layout.tsx#L124)
- **Finding:** Both places hardcode the string `"PT Maju Jaya Kontainer"`. The actual seeded company (via `/api/admin/setup`) is `"PT. Anda"`. The text isn't read from the session or an API at all, it's a hardcoded literal that doesn't match the real record.
- **Reason it fails:** displayed content must come from real data or be an honest placeholder, not an invented value that silently disagrees with the database.

### 4. Fabricated system status
- **Rule:** R-38 (Hard Gate — No Fabricated Claims)
- **File:** [app/dashboard/page.tsx:142-161](app/dashboard/page.tsx#L142-L161)
- **Finding:** The "Status Sistem" card always shows Database = Connected, Authentication = Active, Data Sync = Synced, in green, unconditionally. None of these are backed by a real check; the component always renders the same three green badges regardless of actual state.
- **Reason it fails:** a status claim shown as fact must be real and verifiable, or not shown.

### 5. No mobile layout for the app shell
- **Rule:** R-03 (Hard Gate — Mobile Responsiveness)
- **File:** [components/dashboard-layout.tsx](components/dashboard-layout.tsx) (whole file)
- **Finding:** The sidebar (`w-64` / `w-20`) has zero responsive breakpoint classes (no `sm:`/`md:` collapse, no mobile overlay/hamburger pattern). On a narrow viewport the sidebar still claims 256px (or 80px) of a ~375px screen, permanently, with only a manual expand/collapse toggle that defaults to open.
- **Reason it fails:** mobile layout must be part of the design, not an afterthought; needs verification on an actual small viewport, but the code has no mobile-specific path at all.

### 6. Em dash used as an empty-value placeholder (6 locations)
- **Rule:** R-02 (Hard Gate — Copywriting, literal reading)
- **Files:** [app/sales/rfq/page.tsx:187](app/sales/rfq/page.tsx#L187), [app/operational/products/page.tsx:193](app/operational/products/page.tsx#L193), [app/supply-chain/suppliers/page.tsx:194](app/supply-chain/suppliers/page.tsx#L194)+[202](app/supply-chain/suppliers/page.tsx#L202), [app/sales/quotations/page.tsx:96](app/sales/quotations/page.tsx#L96), [app/sales/customers/page.tsx:192](app/sales/customers/page.tsx#L192)
- **Finding:** `"—"` is used as the fallback for an empty table cell (city, price, title) in 6 places.
- **Note:** the rule's wording bans the em dash character in any text with no carve-out for placeholder symbols, so this is technically a Hard Gate hit. In practice this is low real-world risk (a table dash, not prose) — flagging it honestly per the rule's letter, but it's the cheapest, safest fix on this list (swap `"—"` for `"-"` or `"N/A"`).

## Flagged outside antislop's rule set (found during the audit, worth your attention)

### A. Login page ships with real admin credentials pre-filled
- **File:** [app/auth/login/page.tsx:12-13](app/auth/login/page.tsx#L12-L13)
- **Finding:** `useState("admin@erp.local")` / `useState("admin123")` pre-fill the login form with the real seeded admin credentials, and a "Demo Credentials" box repeats them on screen. This isn't an antislop rule, it's a security exposure: anyone who opens the production login page can log in as admin without being told anything. Recommend removing the pre-fill and the credentials box before this goes further, or gating it behind a non-production flag.
